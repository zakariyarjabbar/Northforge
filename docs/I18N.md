# Language implementation

The site has English (`en`), Arabic (`ar`), and Iraqi Sorani Kurdish (`ckb`). The wordmark remains NORTHFORGE GROUP. Arabic and Sorani use Noto Sans Arabic and right-to-left reading order; photographs, maps and construction geometry keep their original orientation.

## Routes and rendering

English URLs remain unprefixed. The `(english)` route group and `[locale]` route use separate root layouts through `components/site-root.tsx`, so exported documents already contain their language, direction and translated copy before JavaScript runs. The 23 content destinations are reused from `views/` and `lib/page-registry.tsx`, producing 69 content pages. Next.js also emits metadata and not-found entries.

`localePath` and `components/locale-link.tsx` apply the current language to internal links. `withoutLocale` identifies the underlying content path. The selector deliberately loads the destination document when crossing root layouts and retains query parameters and fragments. English has no `/en/` duplicate. The legacy website-information alias exists in all three languages and has the appropriate canonical.

Each page emits localized metadata, its own canonical, and `en`, `ar`, `ckb`, and `x-default` alternatives. The sitemap includes all three public language versions; contact and saved pages remain noindex and excluded. The static unknown-route fallback is the shared English recovery page.

## Copy maintenance

English source strings are translation keys. Both JSON catalogs currently contain 587 keys. The translator normalizes whitespace when looking up a key, preserves outer whitespace required by inline JSX, and interpolates named placeholders such as `{project}` or `{count}`. Missing keys fall back to English; the route-content test catches unexpected visible English on the Arabic and Sorani pages.

When editing copy, update both catalogs in the same change. Preserve placeholder names exactly. Translate content data at the display boundary, including project names, scope, captions, region names, career descriptions and downloaded summaries. IDs, slugs, JSON export fields, stored values, proper names and visitor-authored text remain stable. Search matches localized project information as well as the underlying English name and country.

## Browser state and controls

The URL is the language source of truth. `northforge:v1:language` records the selection without automatically redirecting English URLs. Reloading keeps the language through its URL. Saved projects, inquiry drafts, inquiry references and career profiles share the existing origin and storage keys, so language changes do not duplicate them. Namespace reset removes the preference with the other NORTHFORGE data.

The language dropdown presents native names, has visible selected and focus states, supports Tab, arrows, Home, End and Escape, and closes when focus or pointer moves outside. It remains visible alongside mobile navigation. Empty text fields inherit the page direction; entered visitor text uses automatic direction, and email fields and record IDs stay left-to-right.

## Verification

Run `npm run build`, `npm run typecheck`, `npm run lint`, and `npm run test:flows`. Language coverage is in `tests/languages.spec.ts`; the original user journeys remain in `tests/flows.spec.ts`. See `QA.md` for actual results and visual evidence. No independent native-speaker editorial review was performed.
